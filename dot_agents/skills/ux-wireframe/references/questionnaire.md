# Questionnaire

Questions turn the sources into decisions the wireframe can show. Run them in rounds with the ask tool, so the user answers by clicking.

## How to ask

- **Batch:** one round per call, with four to eight questions and two to five options each. The tool adds "Other" itself.
- **Recommend:** mark one option as recommended, chosen from the sources. Put the source in its description ("Matches Terrence's mock-up", "Workshop: groups first").
- **Trade-offs:** each description says what the option gains and what it costs, in one line.
- **Multi-select:** use `multi: true` for "which of these" questions, such as modules, states and card contents.
- **Skip** any question a source already settles. Use the settled answer and say where it came from in the brief or the notes.
- **Labels:** when the user is unsure of a name ("not sure about Teams"), send two multi-select questions of five options each (one plain set, one brand-led set). Include the client's current label as an option.
- **Vocabulary:** use the client's own words, including what the current site calls things.

## Handling answers

- **Free text:** treat it as a decision. Build what it says, and re-ask only what it leaves open.
- **Screenshots:** a pasted screenshot is evidence. Reconcile it with the concern behind the earlier decision, and propose the option that satisfies both.
- **Interjections:** a mid-build note ("the hero should be full screen") overrides earlier answers. Apply it everywhere it reaches.
- **"Make assumptions":** stop asking. Pick the recommended option for everything left, then record each choice in the relevant page note and in the site map's assumption list.

## Rounds

Adapt each round to the site type. On an ecommerce site the detail page is a product; on a services site it's a service page and checkout becomes booking or contact; on SaaS it's a feature or pricing page. Drop questions that don't apply, and add one wherever the sources raise a decision that's still open.

### Round 1: structure and navigation

1. **Top-level navigation.** Offer three named structures: audience-led, task-led and lean. List the items in each label.
2. **Key section labels**, e.g. a use-case or industry section. Give a longer list if the user hesitates.
3. **Secondary audience doors** (partners, trade, investors). Choose between utility bar + footer + one home module, a top-level nav item, or footer only.
4. **Locator, finder or contact model**, if the site routes people to someone. Choose between a public map, a list behind an enquiry, or matching only. Ask whether it must also work as a modal.
5. **"How it works" content.** Choose between a page plus a home module, a page only, or a module only.
6. **Review states to demo** (multi-select), e.g. guest, signed-in customer, partner view, another market.
7. **Depth of the signed-in area.** Choose between the core task end to end plus an account overview, the core task only, or every account page.

### Round 2: home and listing pages

1. **Mega menu organisation**, e.g. by type first, by audience first, or both columns.
2. **Home module order.** Offer three orders, such as proposition-led, audience-led and product-led, each listed as a numbered sequence in its description.
3. **Optional home modules** (multi-select): testimonials, user content, story or heritage, guides teaser, newsletter band, partner band.
4. **Signed-in home**: the same home with a slim shortcut strip, a redirect to the account, or no change.
5. **Landing page type** for use cases or collections: an editorial hub with a product grid, or a grid with a header block.
6. **Card contents** (multi-select): code or reference, price, key facts, badges, variant count.
7. **Filters**: left sidebar on desktop with a drawer on mobile, or a top bar.

### Round 3: detail page and flows

1. **Detail page actions** when there is more than one route: stacked route cards, tabs, or a primary button with a secondary link.
2. **Primary form container**: side drawer, modal plus standalone page, inline, or page only.
3. **Form structure**: three steps, a single scrolling form, or four steps.
4. **Adding more items to a request**: search inside the form, or a list that persists across pages (often an extension, so say so).
5. **Price, availability or stock display**, and where it appears.
6. **Below-the-fold sections** (multi-select).
7. **Signed-in detail layout**, e.g. a full-width order grid, a side column, or a summary that links to a full-screen tool.
8. **Checkout, booking or submission**: one page with sections, or stepped.
9. **Repeat-use tools** such as quick order or reorder: their own page, or a drawer.

### Round 4: content and the rest

1. **Resources and blog**: under About, under How it works, or a top-level item.
2. **About pages** (multi-select).
3. **Pop-up**: show it as a delayed modal with a review toggle, or leave it as an inline band only.
4. **Partner or trade landing**: one page with an application form, or a landing page plus separate benefit pages.
